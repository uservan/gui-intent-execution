# 运行交接：先收完整轨迹，再做多意图分析

当前仅文档，尚无可执行 runner 或完成的实验。实现者按此顺序推进；不要宣称文档中的占位命令/文件已经存在。

## 1. 固定上游与模型

- 获取 OSWorld-Verified 的明确 commit 和 Ubuntu 镜像，记录 evaluator、任务配置。
- 下载三个 checkpoint：tencent/UI-Mate-9B、tencent/UI-Mate-27B、mPLUG/GUI-Owl-1.5-8B-Think，锁定 revision。
- 使用官方单 agent prompt/parser；UI-Mate 不给示范，GUI-Owl 不启用多 agent framework。
- 使用官方部署建议，经烟测确认暴露完整 reasoning、全部 actions；不只读取 response.content 后遗漏其他响应字段。
- 模型服务与桌面 VM 可以分离，先测 VM 的桌面渲染、输入响应、截图与应用加载。环境过慢会制造虚假的重复推理。
- 首先保证可重复的正确行为，不以最短 sleep 或最高并发作为目标。并发、服务排队、网络与环境耗时单列。
- 不预先规定 GPU 数量或服务版本：以精确 checkpoint 的官方要求和实测显存决定，最终写入 manifest。

## 2. 建立并冻结任务清单

按 MOTIVATION.md 的五层各随机抽 6 个，seed=42。记录候选池、排除、排序与抽样脚本。
公开任务 ID，三个模型使用同一清单。运行后的模型失败不能成为换任务理由。

## 3. 实现采集与报告

实现规范化 episode runner：
reset -> 保存输入/截图 -> 原生模型 predict -> 保存完整响应与全部 actions -> 按官方语义执行 batch -> 保存结果与新观察 -> 重复 -> 官方 evaluator。

必须实现：
- 50 决策轮次 / 300 基础动作 / 30 分钟保护预算，准确记录停止原因；
- 生成动作列表和实际执行事件分开存储；
- 基础动作计数规则固定；一条按键组合按声明的计数规则计，不用 token 数替代动作数；
- 可见 reasoning、原始请求响应、before/after、token/耗时；
- infrastructure_interrupted 与有效模型失败区分；
- 离线 report.html；
- run_id / attempt_id、重跑与幂等输出目录；
- 自动记录 unsupported action 和解析异常。

不删除官方 batch 中的合法动作，不把首动作之后的动作静默丢掉。
如原生 runner 在 batch 中途停止，保留原因；若要增加审计截图，记录其开销且不改变在线反馈。

## 4. Smoke 与 pilot

1. 同样 2 个任务 × 每模型最多 5 轮，手工检查输出、界面效果与报告。
2. 修复采集/解析问题，再冻结适配器配置。
3. 全部任务 reset 后启动 90 episodes；每条 episode 独立可恢复/可重跑。
4. 保存全部成功、失败和截断轨迹，不只收成功案例。
5. 生成汇总表和样本审计，不在本阶段自动挑“最有利”案例。

## 5. 标注

每模型 100 轮，按任务均衡固定随机抽取。先盲提取 reasoning 意图，再标当前覆盖，再看后续 5 轮。
人工确认后再考虑自动标注扩展，不必先训练解析器或 JEV。

应输出的汇总：
- reasoning 可用率、多意图率；
- generated full/partial/none 覆盖；
- batch_size_generated 与 batch_size_submitted 分布；
- 未完成意图 A/B/C/D 分解；
- 原意图跨后续观察的保持轮数与重复表述；
- 任务成功率（pilot 描述性）及推理/执行/等待开销分解；
- 按任务宏平均与任务级结果，不把大量相关轮次当独立样本。

## 6. 人工辅助验证（pilot 分析后）

选约 20 个可恢复状态；固定原生与辅助分支初态。严格按原 reasoning 已决定的意图执行，不看基线未来和答案。
最多 3 个剩余意图、10 个基础动作、2 个额外修复/前置动作。需要新决策则交回。
记录局部和最终结果，明确人工辅助只估计潜力，不证明自动执行器加速。

## 7. 交付验收

- 精确模型/上游/环境 manifest，以及 30 个真实任务 ID；
- 90 条有效 attempt 或清楚解释缺失与基础设施中断；
- 每任务原始日志、前后截图和可打开的报告；
- 300 轮左右的初步标注及复核记录（不足则如实报告）；
- 分析脚本、汇总 CSV、图表和负结果；
- 约 20 个分叉验证的配对记录，若尚未开展则标 pending。

本轮不做：训练执行器、将 JEV 当既定方法、另外生成 planner 计划、修改 prompt 诱导多步推理、用人工执行时间当自动加速、声称“无人做过”。
